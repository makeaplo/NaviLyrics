# NaviLyrics

NaviLyrics 是一个面向个人使用的原生 iOS 音乐播放器，连接家中 NAS 上的 Navidrome / OpenSubsonic 音乐库，重点提供接近 Apple Music 的播放、歌词和浏览体验。

当前版本：`0.3.0`（build `3`）  
最低系统：iOS / iPadOS `18.0`  
技术栈：Swift 6、SwiftUI、AVFoundation、Observation

## 项目定位

这个项目的使用场景很明确：在家中局域网内连接一个 Navidrome 音乐库，直接串流播放并查看高质量同步歌词。

当前产品边界如下：

- 只维护一个当前连接的 Navidrome 音乐库，不设计多服务器、多音源切换。
- 音频和歌词数据以 NAS 为准，当前不做离线下载。
- 不做面向公众发布的账号体系、云同步或社交功能。
- 不针对弱网场景设计复杂缓存；主要优化家庭局域网内的连续使用体验。

## 已实现功能

### 1. 连接音乐库

- 支持 `http://`、`https://` 和局域网 IP 地址。
- 登录前会先调用 Navidrome / Subsonic 接口验证服务器，再加载音乐库。
- 支持保存服务器地址、用户名和密码，下次启动自动恢复连接。
- 真机优先使用系统 Keychain 保存密码；在 Keychain 不可用的特殊安装环境中，会回退到本机偏好设置，并在设置页提示风险。
- 支持更换服务器或账号、退出登录和清除本机连接信息。
- 已声明本地网络访问权限，并允许家庭 NAS 常用的 HTTP 连接。

### 2. 音乐库首页

首页采用单页音乐库结构，播放页作为音乐库上的二级页面出现。当前包含：

- 继续播放：快速恢复上次正在播放的歌曲。
- 最近播放：按最近播放时间显示本机播放记录。
- 本机常听：按播放次数显示常听歌曲。
- 我的收藏：同步 Navidrome 的歌曲收藏状态。
- 播放列表：进入歌单目录和歌单详情。
- 浏览音乐库：进入全部专辑和全部艺术家。
- 最近添加：显示 Navidrome 返回的最新专辑。
- 下拉刷新音乐库、收藏和当前页面数据。
- 服务器刷新失败时保留已有内容，并显示可重试的错误提示，不会直接清空当前页面或停止播放。

播放中的歌曲会显示在底部迷你播放器中；点击迷你播放器即可进入全屏播放页。

### 3. 专辑和艺术家

#### 专辑

- 查看全部专辑。
- 网格视图和列表视图切换。
- 按最近添加、专辑名称、艺术家、发行年份排序。
- 视图方式和排序方式会保存在本机。
- 进入专辑详情查看曲目。
- 支持播放整张专辑、随机播放、逐首播放。
- 支持对专辑执行下一首播放、加入播放队列和加入歌单。

#### 艺术家

- 查看全部艺术家。
- 按首字母分组。
- 提供横向首字母快速跳转。
- 进入艺术家详情查看其专辑。
- 从艺术家专辑继续进入专辑详情和播放流程。

### 4. 搜索

搜索音乐库时会同时返回并分类显示：

- 歌曲
- 专辑
- 艺术家
- 播放列表

搜索结果支持按类型筛选：全部、歌曲、专辑、艺术家、播放列表。筛选按钮会显示各类型结果数量，并提供搜索中、无结果、失败重试等状态。

歌曲搜索结果可以直接播放、收藏，也可以通过长按打开快捷操作。

### 5. 收藏

- 查看 Navidrome 中已收藏的歌曲。
- 收藏状态与服务器同步。
- 支持在歌曲行、搜索结果、专辑详情、播放列表详情中收藏或取消收藏。
- 收藏列表支持播放和刷新。

### 6. 播放列表

支持与 Navidrome 同步的基础歌单管理：

- 查看歌单列表。
- 新建播放列表。
- 重命名播放列表。
- 删除播放列表。
- 查看歌单内的歌曲。
- 播放整张歌单或随机播放。
- 搜索歌曲并添加到歌单。
- 从歌单移除歌曲。
- 对歌单中的歌曲执行播放、收藏和快捷操作。

当前不支持直接拖动调整 Navidrome 播放列表内部的歌曲顺序；播放队列本身支持调整顺序。

### 7. 播放器

- 支持 Navidrome 返回的原格式音频串流，例如 FLAC、MP3 等。
- 支持播放单曲、专辑、播放列表、搜索结果和收藏列表。
- 支持上一首、下一首、自动切歌和重新播放。
- 支持拖动播放进度并同步更新歌词高亮位置。
- 支持播放失败提示和重试。
- 支持播放队列中的当前歌曲、接下来播放和已播放分组。
- 支持从队列删除歌曲、拖动调整队列顺序和清空待播内容。
- 支持把当前播放队列保存为 Navidrome 播放列表。
- 支持播放状态恢复：真实 Navidrome 连接会保存当前队列、当前歌曲和播放进度，下次进入音乐库时尝试恢复。
- 支持后台音频播放。
- 支持锁屏、控制中心、耳机等系统媒体控制。
- 支持音频中断和音频输出设备变化处理。

播放器页面使用专辑封面作为背景，支持从底部迷你播放器自然展开，并可通过下拉手势关闭回到音乐库。系统开启“减弱动态效果”后，会自动降低或关闭主要页面转场动画。

### 8. 同步歌词

歌词加载优先级：

1. 优先读取 OpenSubsonic 结构化歌词和逐字时间。
2. 服务器不支持结构化歌词时，回退到传统歌词接口。
3. 支持逐行 LRC 和纯文本歌词。

当前歌词体验包括：

- 根据播放进度自动滚动和高亮当前歌词行。
- 逐字同步高亮和逐字辉光效果。
- 普通逐行歌词的模拟逐字效果。
- 长音强调和高亮渐变。
- 翻译显示，可选择只显示当前行或全部歌词行。
- 罗马音显示，可选择只显示当前行或全部歌词行。
- 间奏倒计时。
- 点击歌词跳转到对应播放位置。
- 滚动歌词后自动跟随播放位置。
- 可选的长按歌词分享入口。
- 无歌词时显示明确的空状态和重试按钮。

### 9. 本机播放记录

- 记录已经达到有效播放时长的歌曲。
- 首页显示最近播放和本机常听。
- 支持查看完整的最近播放、常听列表。
- 每个 Navidrome 服务器地址分别保存播放记录。
- 最多保留当前服务器最近的 100 首记录。
- 播放记录只保存在本机，不上传到 Navidrome。
- 设置页可以清除当前音乐库对应的本机播放记录。

### 10. 歌词和辅助功能设置

设置页提供以下可调参数：

- 歌词字号、字重、行间距。
- 是否显示翻译和罗马音。
- 翻译和罗马音显示当前行或全部歌词行。
- 逐行歌词和逐字歌词的时间校准。
- 逐字高亮、普通歌词模拟逐字、歌词辉光。
- 间奏倒计时。
- 高帧率歌词动画开关。
- 滚动后自动跟随播放。
- 点击歌词跳转。
- 长按歌词分享。
- 恢复默认歌词设置。

这些设置会持久化保存到本机。界面同时提供 VoiceOver 标签、操作提示和减弱动态效果适配。

## 开发演示模式

Debug 构建包含一个隐藏的本地演示入口，方便在没有连接家中 NAS 时开发和验证 UI：

1. 打开 Debug 构建的 NaviLyrics。
2. 在连接页连续轻点 `NaviLyrics` 标题 7 次。
3. 确认进入“开发演示模式”。

演示模式使用本地虚拟专辑、歌曲、艺术家、播放列表和歌词数据：

- 不连接 NAS。
- 不访问真实 Navidrome 账号。
- 不修改服务器收藏或歌单。
- 不播放真实音频，播放进度由本地模拟。
- 适合外出开发和验证导航、搜索、歌词和播放队列交互。

退出演示模式可以回到连接页；已经保存的真实服务器账号不会被删除。

## 真机运行

### 环境要求

- macOS
- Xcode 26 或更新版本；当前工程使用 Swift 6
- iPhone / iPad：iOS 或 iPadOS 18.0 或更新版本
- 一个可访问 Navidrome 的网络环境

### 使用 Xcode 运行

1. 打开 `NaviLyrics.xcodeproj`。
2. 选择 `NaviLyrics` Scheme。
3. 在 `Signing & Capabilities` 中选择自己的 Apple Developer Team；如果 Bundle Identifier 冲突，可以改成自己的标识符。
4. 连接并解锁 iPhone，必要时在设备上信任开发者并开启开发者模式。
5. 选择真机作为 Run Destination，点击 Run。
6. 首次进入连接页，填写 Navidrome 地址、用户名和密码。

服务器地址可以填写完整 URL，也可以填写局域网地址，例如：

```text
http://192.168.31.125:4533
https://music.example.com
```

如果使用的是家庭 NAS，请确认 iPhone 和 NAS 在同一局域网，且 Navidrome 监听地址允许手机访问。

## 生成 LiveContainer IPA

工程提供了无签名 Release IPA 构建脚本：

```bash
chmod +x build_ios_unsigned.sh
./build_ios_unsigned.sh
```

产物位置：

```text
build/NaviLyrics-iOS18-LiveContainer.ipa
```

如果当前命令行 Xcode 不完整，可以指定 `xcodebuild`：

```bash
XCODEBUILD_BIN=/path/to/Xcode.app/Contents/Developer/usr/bin/xcodebuild \
  ./build_ios_unsigned.sh
```

导入 LiveContainer 后，需要对 NaviLyrics 执行 `Force Re-sign App`。这是原生 Swift 应用，不需要开启 `Launch with JIT`。

更具体的 Mac、Xcode 和 LiveContainer 说明请参阅 [README-MAC.md](README-MAC.md)。

## 测试与验证

工程包含 `NaviLyricsCoreTests`，覆盖以下核心逻辑：

- 重复时间戳歌词的唯一身份。
- 翻译和罗马音附加时的歌词身份保持。
- LRC 解析和异常时间戳过滤。
- 同一时间多行歌词的播放时间线选择。
- 带鉴权封面 URL 的稳定性和敏感信息保护。
- 演示客户端的本地音乐库和歌词。
- 无效播放时长保护。
- 本机播放记录、播放次数和按服务器隔离。

在 Xcode 中选择对应 Scheme 后使用 `Command-U` 运行测试。普通 App 真机运行只构建 `NaviLyrics` 应用 target，不等同于已经运行了单元测试。

## 工程结构

```text
App/                    应用入口、根导航和播放器呈现层
Core/Subsonic/          Navidrome/OpenSubsonic 客户端、会话和数据模型
Core/Playback/          AVPlayer 播放器、队列、播放记录和设置
Core/Lyrics/             歌词模型、解析、时间线和歌词运行时
Features/Authentication/ 登录和连接流程
Features/Library/        音乐库、专辑、艺术家、收藏和播放列表
Features/Player/         播放页、队列和同步歌词界面
Features/Settings/       连接、歌词和播放记录设置
Shared/Components/       歌曲行、封面、收藏按钮等共享组件
Tests/                   核心逻辑测试
Config/Info.plist        本地网络、后台音频和设备配置
```

## 当前限制

以下内容目前明确不在本阶段范围内：

- 离线下载音频。
- 面向弱网的完整本地内容缓存。
- 多服务器、多账号、多音源管理。
- Navidrome 播放列表内部歌曲的拖动排序。
- App Store 正式发布和公共账号体系。

这些限制不影响当前的核心使用链路：连接家中 Navidrome → 浏览音乐库 → 播放 → 查看同步歌词 → 管理队列和歌单。

## 设计原则

- 以音乐库为一级入口，以播放页为自然的二级页面。
- 尽量保持 Apple Music 风格的连续播放体验，但不引入多余的音乐源和复杂账户层级。
- 播放和歌词优先，浏览、搜索和队列操作围绕“快速开始播放”组织。
- 对局域网使用场景保持直接，对离线下载、弱网缓存等非核心能力保持克制。
